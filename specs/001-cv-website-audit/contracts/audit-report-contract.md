# Contract: Audit and Improvement Reporting

## Purpose
Define the expected structure for audit results and implementation verification
artifacts generated by this feature.

## Input Contract

### Audit Scope Input
- `pages_in_scope`: list of page paths (required)
- `shared_assets_in_scope`: list of shared files/directories (required)
- `constraints`: includes GitHub Pages/Jekyll compatibility (required)

### Validation Policy Input
- `a11y_target`: must be `WCAG 2.2 AA`
- `performance_targets`: must include `LCP <= 2.5s`, `CLS <= 0.1`, `INP <= 200ms`
- `external_link_policy`: minimum 3 retries before `broken`
- `factual_change_policy`: explicit owner approval required

## Output Contract

### Audit Findings Output
A collection of `AuditFinding` items where each item includes:
- `id`
- `category`
- `severity`
- `page_or_asset`
- `description`
- `evidence`
- `recommendation`
- `requires_owner_approval`
- `status`

Validation rules:
- Missing `severity`, `evidence`, or `recommendation` invalidates the output.
- Each finding category must map to one of the five mandated domains.

### Recommendations Output
A collection of `RecommendationItem` items where each includes:
- `id`
- `title`
- `priority`
- `effort`
- `expected_impact`
- `linked_findings` (>=1)

Validation rules:
- A recommendation without linked findings is invalid.
- Priority must be one of `p1`, `p2`, `p3`.

### Improvement Verification Output
A collection of `ImprovementItem` items where each includes:
- `id`
- `recommendation_id`
- `changed_files`
- `build_validation`
- `a11y_validation`
- `seo_validation`
- `performance_validation`
- `final_status`

Validation rules:
- `build_validation` must be recorded for every implemented item.
- `recommendation_id` must reference an existing recommendation.

### Link Validation Output
A collection of `LinkCheckRecord` items where each includes:
- `url`
- `link_type`
- `attempts`
- `attempt_results`
- `final_classification`
- `classification_reason`

Validation rules:
- External links classified as `broken` must show `attempts >= 3` with consistent failure.
- Unstable outcomes must be classified as `inconclusive`.
